# 14 — Finance Domain Evaluation

> **Document Type:** AI Quality Gate / Audit Specification  
> **Project:** Personal OS  
> **Phase:** F7 — Finance Domain

## 1. Purpose

Đây là Quality Gate sau khi hoàn thành F7.

AI không dùng file này để code feature mới trước tiên, mà dùng để:

```text
Audit Architecture
Audit Database
Audit Business Logic
Audit Transaction
Audit Security
Audit API
Audit Frontend
Audit Testing
Audit Performance
→ GO / CONDITIONAL GO / NO-GO
```

Đánh giá phải dựa trên:

```text
actual source code
database schema
migrations
tests
runtime behavior
documentation
```

Không đánh giá bằng assumption.

## 2. Mandatory Audit Procedure

AI MUST:

```text
1. Read F7 documentation
2. Read MapNode
3. Inspect project structure
4. Inspect Finance database schema
5. Inspect migrations
6. Inspect repositories
7. Inspect services
8. Inspect APIs
9. Inspect validation
10. Inspect frontend
11. Inspect tests
12. Run typecheck
13. Run lint
14. Run unit tests
15. Run integration tests
16. Run E2E where available
17. Audit security
18. Audit Transaction invariants
19. Audit balance consistency
20. Audit performance
21. Score
22. Identify blockers
23. Generate remediation plan
24. Decide GO / NO-GO
25. Update MapNode only when verified
```

## 3. Scoring

```text
0 = Not implemented
1 = Critical problems
2 = Major improvements required
3 = Acceptable MVP
4 = Good
5 = Production-ready
```

Recommended weights:

| Category | Weight |
|---|---:|
| Transaction Correctness | 20% |
| Data Integrity | 15% |
| Security & Authorization | 15% |
| Backend/API | 10% |
| Testing | 15% |
| Architecture | 10% |
| Frontend/UX | 5% |
| Performance | 5% |
| Documentation/Maintainability | 5% |

Total:

```text
100%
```

## 4. Automatic NO-GO Conditions

Any of these means NO-GO:

```text
[ ] Cross-user Finance data access
[ ] IDOR vulnerability
[ ] Balance inconsistency
[ ] Non-atomic transfer
[ ] Transaction mutation bypasses authorization
[ ] Unsafe floating-point financial calculation
[ ] Transaction without ownership validation
[ ] Account/category ownership bypass
[ ] Critical financial tests fail
[ ] Production build fails
```

## 5. Architecture Audit

Check:

```text
[ ] Finance follows project architecture
[ ] Business logic is outside React components
[ ] Routes/controllers are thin
[ ] Services contain orchestration
[ ] Repositories contain persistence
[ ] Shared infrastructure is reused
[ ] No duplicate auth system
[ ] No duplicate Design System
[ ] No unnecessary abstractions
```

AI must provide evidence:

```text
file path
function/class
test
```

## 9. Transaction Audit

This is the highest-priority audit.

Verify:

```text
[ ] Income
[ ] Expense
[ ] Transfer
[ ] Amount validation
[ ] Currency validation
[ ] Account validation
[ ] Category validation
[ ] Ownership
[ ] Authorization
[ ] Transaction date
[ ] Create
[ ] Read
[ ] Update
[ ] Delete/void
[ ] Search
[ ] Filter
[ ] Pagination
```

## 10. Transaction Invariant Audit

Run:

### Income

```text
Before = 1,000,000
Income = 500,000
After must equal 1,500,000
```

### Expense

```text
Before = 1,000,000
Expense = 200,000
After must equal 800,000
```

### Transfer

```text
A = 5,000,000
B = 2,000,000
Transfer = 1,000,000

A = 4,000,000
B = 3,000,000
Total = 7,000,000
```

## 11. Transfer Audit

Verify:

```text
[ ] Source ownership
[ ] Destination ownership
[ ] Source != destination
[ ] Currency compatible
[ ] amount > 0
[ ] Atomic database transaction
[ ] Source decreases
[ ] Destination increases
[ ] Total money preserved
[ ] Not income
[ ] Not expense
[ ] Rollback tested
```

If partial transfer is possible:

```text
NO-GO
```

## 12. Transaction Update Audit

Test:

```text
amount change
type change
account change
category change
date change
```

For each:

```text
old financial effect reversed
+
new financial effect applied
```

must be atomic.

## 13. Delete/Void Audit

Verify:

```text
[ ] Financial effect reversed
[ ] Transaction state correct
[ ] Balance correct
[ ] Summary correct
[ ] Ownership enforced
[ ] Atomic
```

## 14. Summary Audit

Verify:

```text
Total Income
Total Expense
Net Cash Flow
Total Balance
```

Definitions:

```text
Total Income = income transactions
Total Expense = expense transactions
Net Cash Flow = income - expense
```

Transfers MUST be excluded from income and expense.

## 15. Multi-Currency Audit

Verify:

```text
[ ] Currency explicit
[ ] No silent conversion
[ ] Same-currency transfer rule
[ ] Summary does not combine currencies incorrectly
```

## 16. Authorization Audit

For every resource:

```text
User A → own data → ALLOWED
User A → User B data → DENIED
```

Test:

```text
accounts
categories
transactions
transfers
summary
```

Also test that client cannot override ownership using `userId`.

## 17. IDOR Audit

Attempt cross-user operations:

```text
GET
PATCH
DELETE
```

on another user's resource.

Expected:

```text
403 or 404
```

according to project convention.

Never:

```text
200 + another user's data
```

## 18. Input Validation Audit

Test:

```text
amount = 0
amount < 0
invalid ID
invalid type
invalid currency
missing account
missing category
wrong category type
same transfer accounts
different transfer currencies
invalid date
```

All must fail safely.

## 19. Mass Assignment Audit

Attempt to submit protected fields:

```text
userId
createdAt
updatedAt
ownerId
```

Server must ignore or reject them.

## 31. Evidence Rule

For every important score, provide evidence such as:

```text

schema
migration
test name

```

Example:

```text

Evidence:

```

## 32. Unknown State

If something cannot be verified:

```text
UNKNOWN
```

Do NOT convert unknown into PASS.

Example:

```text
Production concurrency behavior = UNKNOWN
```

## 33. Score Calculation

Calculate:

```text
weighted score = Σ(category score × category weight)
```

Convert to:

```text
0–100
```

## 34. Readiness

### GO

Recommended:

```text
>= 90/100
```

and:

```text
No critical issue
No automatic NO-GO
Critical tests pass
```

### CONDITIONAL GO

```text
80–89
```

Only if:

```text
No security critical issue
No financial integrity issue
No critical test failure
```

AI must list remediation tasks.

### NO-GO

Any:

```text
financial integrity issue
critical security issue
cross-user access
broken transfer atomicity
critical test failure
```

means:

```text
NO-GO
```

regardless of score.

## 36. Severity

Use:

```text
CRITICAL
HIGH
MEDIUM
LOW
INFO
```

### CRITICAL

Examples:

```text
financial corruption
cross-user access
security compromise
```

### HIGH

Major business behavior broken.

### MEDIUM

Important but contained problem.

### LOW

Minor quality issue.

### INFO

Suggestion.

## 37. Remediation Priority

Always fix:

```text
1. Financial integrity
2. Security
3. Authorization
4. Data consistency
5. Critical backend bugs
6. Tests
7. UX
8. Performance
9. Refactoring
10. Visual polish
```

## 38. AI Self-Approval Rule

AI MUST NOT say:

```text

```

without inspecting:

```text
source
schema
tests
runtime
```

Explicitly distinguish:

```text
VERIFIED
```

from:

```text
ASSUMED
```

and:

```text
UNKNOWN
```


## 40. Post-Evaluation

If:

```text
GO
```

then:

```text
Freeze F7
→ Update MapNode
→ Start F8 Architecture Review
```

If:

```text
CONDITIONAL GO
```

then:

```text
Create remediation tasks
→ Fix HIGH issues
→ Re-evaluate
```

If:

```text
NO-GO
```

then:

```text
Do not start next major domain
→ Fix blockers
→ Run evaluation again
```

## 41. Final Principle

Mục đích của evaluation không phải để đạt điểm cao.

Mục đích là ngăn Finance Domain được xem là hoàn thành khi dữ liệu tài chính còn có thể sai hoặc bị truy cập trái phép.

```text
Evidence
>
Tests
>
Invariants
>
Security
>
Score
```

Nếu tiền có thể bị ghi nhận sai:

```text
Finance is NOT ready.
```
